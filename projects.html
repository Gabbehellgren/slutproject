2. Background

2.1 Idea 1

Everything started when I was vibe-coding with Claude. I first tried to create a program for an encrypted chat room that I could use with my friends. The program was mostly meant to be a fun thing. Since it was mostly a fun mini-project, I decided to implement commands that would allow me to play harmless pranks on my friend's computer (e.g. shake the mouse pointer).

2.2 Idea 2

I thought the prank part was fun, so I dropped the whole chat idea. Instead, I came up with the idea of making a program that would give me a backdoor into several of my friends' computers and let me perform pranks. I started trying to develop my new project with Claude. But Claude refused to help me develop my idea. Claude explained to me that what I wanted to do was called a RAT, which is generally unethical and in almost all cases is classified as malware.

2.3 What is a RAT?

I can start by saying what RAT stands for since the name gives a fairly clear picture of what it is. RAT stands for Remote Access Trojan. In other words, it lets someone from afar access and control a computer using a trojan program. A trojan program is like the story of the Trojan Horse: something that looks good on the outside but can do terrible things in reality. A RAT program is a program that masks itself as a legitimate program but can in the background execute code, monitor the user, steal login credentials/passwords/codes, and much more. The data it collects is sent to the person behind the program.

3. Description

3.1 Overview

My RAT consists of several parts. These are described below. Together they form a system that allows me to joke a little with my friends and is developed from a research perspective as well as to improve my knowledge of cybersecurity, network infrastructure, and how to manage a larger programming project.

3.2 Server Program ("Victim")

The server program is the program that the "victim" has been injected with. Its main tasks are advertising itself, being connectable, handling good/bad connections, and then executing the pranks I want to implement.

The advertising is that the program shouts out on the network "I am here." In practice, it will send the computer name (hostname) to the broadcast IP address. This broadcast can be picked up by the admin program and shows me which "victim" is currently active and available to connect to. However, this method allows more people than me to read it, which means a security risk for the "victim."

I am not a fan of security risks, so to handle dangerous connections the program automatically takes care of them. Therefore, the program should have a dedicated function for this.

In addition, what can be executed will be predetermined to prevent malicious use.

I want to protect the "victim" as much as possible from strangers.

3.3 Client Program (Me/admin)

The admin/client program is the program that finds and connects to the victim computer. The program's interface should be CLI-based (similar to the Linux terminal) to be easy to use and also look cool.

3.4 Encryption Module

To protect the "victim" more, I also want to develop my own encryption algorithm to share encrypted keys that no one can read or know what they are. (If I have time)

3.5 Injection Program (Trojan)

This program is responsible for injecting the server program. The idea is that the trojan program should be a program that on the surface looks like just a game or something similar. But in reality the server file is placed in the folder for programs that start automatically.

3.6 Why is my RAT ethical? (Summary)

Why is my RAT more ethical than others? Answer: It is not ethical. This program is by definition malware. But that does not mean it is not designed to be malicious, permanent, or intended to destroy. Yes, it will be annoying and yes it will be difficult to find and neutralize on its own. But it is precisely that: annoying and not permanent. This project is developed only for research purposes.

4. Target Audience

People who want to learn more about how this works and also have an interest in programming and networking.

5. Functional Requirements

5.1 Server Program ("Victim")

  1. Advertise itself.
  2. Set up a server that a client can connect to.
  3. Be able to see if incoming connections are bad and then drop the connection and shut down the program for that run.
  4. Send descriptive debug output in the terminal.
  5. The program should be able to remove itself when I want. (Self destruct)

5.2 Client Program (Me/admin)

  1. Have a command line interface that is functional but also aesthetic.
  2. Be able to discover the "victims" and sort out any leftovers.
  3. Connect to them and be able to send commands.

5.3 Encryption Module

  1. Be able to encrypt passwords but also do it efficiently.

5.4 Injection Program (Trojan)

  1. A beautiful front and horrible back.
  2. Move the file to the right folder.

6. Technical Choices

6.1 Overview

  1. Uses Python because it is the language I know best. I use the socket module to handle the networking part.

6.2 Server Program ("Victim")

  1. Advertises itself with UDP packets on the broadcast IP address; UDP because they are fast and it does not matter if they arrive or not.
  2. Uses TCP so the packets arrive.

6.3 Client Program (Me/admin)

  1. Chose a simple interface because it is cool and you can make it look quite nice.
